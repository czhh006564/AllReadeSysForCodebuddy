**版本：V1.0**  
**适用技术：微信原生小程序 + CloudBase云开发**  
**文档用途：数据库建设 / 云函数开发 / 接口设计 / 测试 / 数据治理**

---

# 一、数据库设计目标

本数据库不是围绕页面设计，而是围绕长期稳定的业务对象设计。

核心保证：

1. 学生身份永久；
2. 图书身份永久；
3. 阅读关系可追溯；
4. 数据全部可审计。

# 三十一、reader_sequence原子生成

开启阅读事务：

1. 锁定book_instance；
2. 读取reader_count；
3. 新序号 = reader_count + 1；
4. 创建reading_relation；
5. 更新reader_count；
6. 提交。

# 七十一、数据库核心验收标准

必须验证：

- 学生升年级student_id不变；
- 多微信绑定同一学生；
- 一个微信多个学生；
- 物理载体更换book_uid不变；
- 第X位小读者原子生成；
- 一书一当前阅读者；
- 正常投放不逐本；
- 正常回收批量；
- 异常才扫码；
- 删除行为用反向荣誉流水；
- 跨班隐私匿名。

# 七十二、数据库最终设计思想

系统真正核心数据结构是：

> **学生永久身份 + 图书永久身份 + 一次次真实阅读关系**

最重要的三个主键：

> **student_id**

> **book_uid**

> **reading_relation_id**
